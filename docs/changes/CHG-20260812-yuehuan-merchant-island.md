# CHG-20260812-yuehuan-merchant-island: 月环商岛可探索场景与实体商人

- Status: done
- Type: feature
- Owner: Codex
- Created: 2026-08-12

## Goal and player/project outcome

把现有“进入后直接显示商城”的月环商港改造成可探索的小型商岛。玩家从码头登岛，沿岛上道路走到不同商铺门前，与实体商人交谈后打开各自负责的交易界面，使商城成为世界中的地点和人物，而不是脱离场景的总菜单。

## Scope

- 使用一张完整生成式大地图承载月环商岛，延续伏波古岭的单图背景、Godot 覆盖角色/UI、粗略手工碰撞方案。
- 地图包含码头、中央商街、货栈、造船图纸铺/船行和足够清晰的步行道路。
- 商岛必须第一眼呈现繁忙商行聚落：码头连接连续石板商街，至少形成多间相连铺面、货棚/摊位、仓储货堆和船行业态，不能以两栋孤立建筑加大面积空地表现成荒岛据点。
- 生成并导入两名实体商人：货栈商人与船行掌柜。
- 两名商人必须是与现有主角同尺度的 Q 版像素小人（约 2.5～3 头身），不得使用写实成人比例或缩小立绘冒充地图角色。
- 玩家可在岛上行走，接近商人后按 `E` / 空格交互，先出现简短对话，再由对话选项打开对应交易界面。
- 货栈商人负责木材和铁石的购买/出售，同时收购所有可出售特产、海货与杂物。
- 船行掌柜负责一次性船型图纸购买及已解锁船型的重复建造。
- 复用现有 `GameState`、`ItemCatalog`、`EconomyState`、`TradeService` 和返航上下文，不改变价格、初始资源、舰队上限与存档格式。
- 保留全局物品栏入口；交易 UI 打开时停止角色移动，关闭后恢复。

## Non-goals

- 不制作商铺室内场景、复杂门体动画、NPC 日程、昼夜、动态物价或商人好感。
- 不制作像素级精细碰撞或寻路网格；首版只沿海岸、建筑和不可达装饰设置粗略边界。
- 不增加修船、出航消耗品、采集工具、装备商店、付费内容或新商品。
- 不拆分货栈的木铁交易商与收购商；首版由同一名商人承担两项职责。

## Constraints and risks

- 当前工作区包含尚未提交的上一轮月环商港与 V4 迁移修改；本变更在其上增量开发，不覆盖或清理用户已有改动。
- 生图地图必须留出清楚、宽阔、连续的道路，并避免人物、文字和 UI；碰撞按照实际生成图手工拟合。
- 第一张生成候选因“仅两栋孤立建筑、中央空地过大、缺少连续店铺和港口货运细节”被拒绝，不得作为正式背景；正式候选需同时满足可走性与商贸密度。
- 商人透明素材使用纯色键背景生成并本地抠图；必须按 Q 版地图小人审查头身比、轮廓和 64×64 主角并排尺度，不能把写实比例立绘直接缩小使用。如边缘质量不满足场景尺度，优先重新生成，不用代码图形替代。
- 当前会话未暴露 Godot AI MCP 可调用工具；使用 Godot 4.7 编辑器/命令行加载、指定场景运行、截图和节点检查完成验证，并在最终证据中记录该限制。
- 代码审查补充（2026-08-12）：实现必须显式接入共享 `ExplorationUI` 以保留物品栏；造船页只能列出已解锁船型；码头粗碰撞必须只在石质步道范围留口并在栈桥尽头封住海面；自动化必须至少有一条通过真实 `Area2D` 重叠与 `interact` 输入完成商人开店/码头返航的路径。
- 用户二次视觉验收（2026-08-12）：`yuehuan_merchant_island_v2.png` 商铺、摊位、货物与码头设施过密，主路狭窄且碰撞需要逐物件拟合，不再作为正式场景背景。第三版必须参考伏波古岭的空间组织：地图只在下方/左下方出现单侧海岸，陆地延伸至其余三边；使用大块干净可走地面、宽阔主路、少量明确功能建筑和自然边界，碰撞只覆盖海岸、建筑主体和极少数大型物件。
- 用户三次视觉验收（2026-08-12）：V3 的宽路、单侧海岸和简单碰撞方向保留，但两栋核心建筑缺少招牌，远看像普通仓房。不得重新堆叠摊位；改为在门面叠加同风格大型木质悬挂招牌，图形符号区分货栈与船行，准确中文由 Godot 文字节点叠加。招牌仅为视觉与导视层，不产生碰撞。
- 用户四次视觉验收（2026-08-12）：V3 加装大型招牌后仍被否决。根因不是招牌大小，而是两栋建筑仍是“不知名路边小店”的体量与组织，后贴招牌显得突兀。V4 必须重新生成整张背景，改为月环商港总埠：中央码头轴线连接开阔交易前庭；左侧是一组围合式货栈院落和装卸设施；右侧是宽体船行工坊、船架与半成品船体。建筑群应像有官方许可、长期经营的大型商号分部，而不是两间孤立小铺。继续保留单侧海岸、宽阔主路、门前空场和少量粗碰撞；不得用密集摊位或漂浮超大 UI 式招牌制造商贸感。
- 用户商城 UI 验收（2026-08-12）：现有半透明双列表像“政府采购系统”，不是玩家浏览商品的商城。根因是共享 HUD 未在商城状态隐藏、商品只有长条文字按钮、缺少图标橱窗与选中焦点。新版使用全屏不透明/高遮蔽店铺层；顶部仅保留商人/店铺身份与关闭；左侧为店铺商品卡片，中间为大图与价格/用途详情，右侧为玩家仓库格；底部聚焦数量、总价和主操作。货物图标由生图模型生成统一像素资产，船图只使用用户美术组素材。
- 用户商城 UI 二次否决（2026-08-12）：第一轮重做虽有图标与 HUD 隔离，仍被评为最多 3/10。联网调研后确认其仍是“三个等宽深色后台面板”的复用式布局，缺少实体商铺关系和唯一视觉焦点。最终版不直接复制第三方资产，但采用成熟 JRPG/战棋商店的任务层级：左侧商人/店铺氛围固定，中间单列可快速浏览商品，右侧纸质详情与大图承担唯一焦点；库存通过“出售”模式进入同一列表，不与商店列表同屏竞争。
- 本地 1344×896 视觉复核（2026-08-12）：非对称版仍有两项阻断验收的问题。其一，禁用态被用作当前页签，导致“出售货物/船坞建造”看起来像当前模式，而详情与操作仍处于购买模式；必须改为明确的高亮选中态，并同步列表标题、价格文案和唯一主按钮。其二，巡哨快船大图左侧残留同图其他舰船碎片，正式商城资产必须重新清理到单船透明图。
- 用户商城 UI 三次否决（2026-08-12）：廉价感的明确来源是大量无意义方框、大量无意义文字、以及相互争抢且低可读的配色，尤其是文字颜色。下一版不再通过套框表达层级：只保留商品主展台、数量输入和主操作等有交互/承载意义的容器；商人区、页签、商品行、资源信息使用留白、细分隔线和选中标记组织。删除重复区块标题、重复店名、商人口号和不影响购买判断的来源长文。正文统一深墨色，辅助信息统一灰褐色，铜金只用于价格、当前选择和主操作，禁止浅黄文字置于米黄纸面。
- 用户场景比例验收（2026-08-12）：两名商人的地图形象明显大于 64×64 玩家。按透明像素实际包围盒测得玩家可见高度 50 px，梁货郎原图可见高度 769 px、沈船师 712 px；原缩放 `0.085` 分别形成约 65 px 与 61 px 高角色。地图商人统一改用 `0.065` 基准（约 50 px 与 46 px），并重新校准脚底位置，不改变商城内商人展示尺寸。
- 用户商人站位与环境对白验收（2026-08-12）：梁货郎从货栈门前右侧移到用户截图箭头所示的门前左下位置。首轮按世界坐标 `Vector2(370, 655)` 放置后被左侧任务栏遮挡，第二轮 `Vector2(430, 655)` 仍有部分人物轮廓压在任务栏边缘；最终依据当前相机偏移实机校准为 `Vector2(460, 655)`，确保人物完整可见且不堵住货栈门口或主路，气泡向人物右上方展开避让任务栏。两名商人在探索状态可于头顶随机显示一句短促吆喝气泡；气泡仅作环境演出，不自动触发对话。玩家仍须进入交互范围后按 `E/空格` 才打开满屏对话；满屏对话、商城及全局菜单开启时气泡立即隐藏并暂停。
- 用户商城交互与空间优化（2026-08-12）：商城主体调整为约 4:6 的“商品列表—商品详情”，NPC 缩为标题栏头像，不再占用独立纵栏。详情大图、核心数值、交易后预览与操作集中排列，减少无效留白。数量框允许直接输入，并提供 `+10`、`+100`、`最大`、`清空`；出售模式另有“全部出售”。数量变化实时预览交易后军饷与持有量，非法数量或资源不足时主按钮禁用。商品行使用图标、名称和右对齐价格；当前标签与商品同时使用浅底/铜金标记，补齐按钮 hover、pressed、disabled 状态。底部资源拆为带像素图标的均匀资源块。因项目仓库无容量上限，“舰船 1/10”不得误写为“货仓容量”，继续准确显示为舰队容量；商品区顶部显示当前商品持有量。
- 用户红线碰撞验收（2026-08-12）：以用户截图红线内部作为唯一可移动区域。换算至 1536×1024 世界坐标后，可走区由三段组成：上部中央商街约 `x=555..970, y=125..545`；中部交易前庭约 `x=175..1215, y=545..700`；下部码头轴线约 `x=555..970, y=700..1024`。最终使用 8 块大矩形拼出红线阶梯轮廓（顶部、上段左右、中段左右、下段左右、码头末端），不保留旧建筑碰撞。红线外的货栈院内、船行作场、建筑、植被、悬崖和海面不可进入；两名商人所在前庭及整条石质码头保持可达。
- 用户红线二次微调（2026-08-12）：可见碰撞截图显示右上街道边界与码头两侧仍偏宽。右上街道边界从 `x=970` 微收至 `x=960`；交易前庭保持不变。前庭进入码头时增加一段粗阶梯：`y=700..730` 可走 `x=570..930`，随后正式码头 `y=730..1024` 收为 `x=590..905`。这样边界贴近截图红线与实际石砌内缘，不把两侧悬崖/海岸空地算作可走区，同时保留中央连续通路。
