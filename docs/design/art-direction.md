# 美术方向

## 角色基准

- 人物采用用户提供的 LPC 独立帧，标准画布为 64×64。
- 原始比例导入，最近邻过滤，不通过缩放掩盖场景比例错误。

## 皇宫背景

- 俯视偏正面的像素 RPG 视角，与四方向 LPC 人物兼容。
- 中式宫殿使用朱红、黛青、暗金和灰石，温润但具有威严。
- 地面纹理清晰但不过密；一名角色的高度约等于庭院石砖宽度的 1 至 1.5 倍。
- 背景不得包含人物、文字、UI、水印、悬崖或楼梯高台。
- 正殿使用剖顶/去屋顶表现，让室内和殿外庭院同时可见；中央门洞必须连续、宽敞、没有透视高度歧义。
- 像素边缘清晰，避免写实光影、模糊笔刷和等距 3D 视角。

## 生成图用途

生成背景是可替换的原型资产。先验证角色比例与可走空间，再进入场景实现。

## 场景二对话 UI

- 全宽对话区域使用 `assets/ui/paper/PNGs/Backgrounds/BackgroundBar.png` 作为底板，不再使用程序生成的米黄色长方形边框。
- 当前版本按方案 A 将用户重新裁剪的 512×144 原图整体拉伸到既有 1344×190 对话区域；黑色描边外侧白底使用透明通道显示游戏背景，描边和框内米白纸张保持不透明；不做九宫格、切片拼接或二次裁剪。
- 人物立绘、人物名牌、正文、选项按钮以及四周黑色长条继续使用既有位置、尺寸、颜色和层级。

## 探索 HUD

- 探索 HUD 参考东方武侠游戏常见的角落式布局：左上主角徽章、左侧任务卷轴、右上菱形功能入口；只模仿信息层级和视觉语言，不复用参考图的游戏背景、人物或特效。
- UI 使用黛青黑、旧纸米色和低饱和铜金作为主色，细描边、切角和轻微阴影形成古朴金属与纸张叠层；保持半透明，让世界画面仍然可读。
- 左上主角状态区只裁切显示 `assets/characters/protagonist/picture.png` 头像，并以“水师主帅”名牌标识；生命、气力、等级等未定状态不做占位条。
- 左侧任务栏使用紧凑尺寸固定区分“主线”和“支线”，尽量减少对世界画面的遮挡；每项可带圆形人物占位徽记、任务名和简短目标。具体任务卡使用透明背景，仅保留轻量边框、分类色条和文字层级；它是效果展示，不表达已完成的正式任务数据系统。
- 右上功能区从左到右按“人物、物品栏、船只、菜单”排列，使菜单固定在最右侧；每个菱形按钮同时具有简洁符号和常显名称，不能依赖悬停提示才能识别。
- “人物、物品栏、船只”入口当前只反馈功能即将开放；最右侧“菜单”入口展开中央系统面板。
- 探索主界面的主角状态框、任务栏边框和功能按钮底框使用专门生成并去除色键背景的水墨风透明 PNG 组件：以墨色干湿笔触、宣纸留白和黛青墨韵为主体，只用少量暗金细线收边；主角状态框由左侧菱形头像座连接右侧宣纸名牌，任务栏只保留顶部题签和轻量墨线外框且中部完全透空，功能按钮使用统一的菱形墨框和黛青内芯。
- 探索 HUD 生成图不得烘焙人物、中文、功能符号或游戏背景，头像、文字、占位徽记和点击区域全部由 Godot 控件覆盖；组件允许按现有控件尺寸整体拉伸，但不得裁掉主要边角装饰。
- 系统菜单沿用黛青黑、旧纸米色和铜金描边，中央纵向排列“继续游戏、保存进度、读取进度、游戏设置、返回标题、退出游戏”，不显示“新手教程”；每项使用左侧菱形符号和常显中文名称。
- 系统菜单打开时以实时屏幕纹理模糊并轻度压暗后方世界及探索 HUD，菜单面板自身保持清晰；右上圆形关闭按钮必须清楚可见。
- 系统菜单框、按钮底板和关闭按钮使用专门生成并去除色键背景的透明 PNG 组件：菜单框强调黛青织物/漆木、旧铜金包边、中式回纹暗纹和略带手绘感的不规则边缘；按钮使用灰白旧纸/石材内芯、墨色描边与左侧菱形徽章座。生成图内不烘焙文字，所有中文由 Godot 控件覆盖绘制。
- 生成组件允许按现有菜单尺寸整体拉伸，但不得裁掉四角装饰、标题牌或左侧徽章座；按钮文字必须落在材质较平静的中部区域，避免纹理影响可读性。
- 系统菜单六个条目使用较舒展的纵向按钮框，文字字号固定为 21；鼠标悬浮不增加底色、不改变字体颜色，只在实际按下时保留轻微反馈。
- HUD 避开底部交互和对话区域，并能随画布尺寸保持在屏幕角落。
