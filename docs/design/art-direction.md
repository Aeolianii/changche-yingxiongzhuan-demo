# 美术方向

## 角色基准

- 人物采用用户提供的 LPC 独立帧，标准画布为 64×64。
- 原始比例导入，最近邻过滤，不通过缩放掩盖场景比例错误。
- 正式主角采用 64×64 年轻中国水师将领像素帧：黑色束发、蓝灰轻甲、朱红短披肩与中式佩刀；待机和行走均为四方向每方向 4 帧，脚底统一位于 y=63，不使用运行时缩放。
- 第一幕皇帝是明确记录的例外：源帧为 128×128 RGBA、四方向待机与行走各四帧；保持源像素与最近邻过滤，仅在皇帝场景实例上使用约 `0.55` 的统一缩放和既有脚底偏移，使可见高度与 64×64 LPC 角色协调。
- 皇帝采用黑金龙纹袍、朱红内衬、暗玉点缀和束发金冠形成身份焦点；它是虚构朝廷人物，不作为真实历史皇帝、服制或仪式的复原。

## 皇宫背景

- 俯视偏正面的像素 RPG 视角，与四方向 LPC 人物兼容。
- 中式宫殿使用朱红、黛青、暗金和灰石，温润但具有威严。
- 地面纹理清晰但不过密；一名角色的高度约等于庭院石砖宽度的 1 至 1.5 倍。
- 背景不得包含人物、文字、UI、水印、悬崖或楼梯高台。
- 正殿使用剖顶/去屋顶表现，让室内和殿外庭院同时可见；中央门洞必须连续、宽敞、没有透视高度歧义。
- 像素边缘清晰，避免写实光影、模糊笔刷和等距 3D 视角。

## 生成图用途

生成背景是可替换的原型资产。先验证角色比例与可走空间，再进入场景实现。

### 月环商岛单图背景与商人

- 月环商岛沿用伏波古岭的单张完整背景方案：约 1536×1024 横向、明朗精致的岭南像素 RPG 3/4 俯视视角；Godot 覆盖角色、碰撞、交互和 UI。
- 月环商岛第三版参考伏波古岭的空间组织：只在下方/左下方设置单侧海岸，陆地向其余三边延伸；不要求四面环海。码头通向至少 220～280 像素净宽的连续主路，中央使用干净夯土/石板地面，避免狭窄巷道。
- 商贸感由“总埠级”空间组织建立，不靠铺满摊位或后贴巨型招牌：中央码头轴线连接开阔交易前庭；左侧使用主仓、侧仓、装卸棚与院墙组成围合货栈院；右侧使用宽体工坊、船架、半成品船体和图纸门廊组成船行作场。
- 货栈与船行是中型公共/行业建筑群，不得画成两栋孤立民居或路边小铺。建筑灰砖黛瓦、镬耳墙与深木门面保持岭南感，可使用克制铜金门饰、行业纹样和比例合理的素面门匾，但不得生成文字。
- 正式场景不使用漂浮的独立超大招牌资产；店名由角色交互提示和商城 UI 准确呈现。门前各留大块空场，陈设只集中在业务院落内，不侵占中央通路。
- 禁止复杂屋群、连续摊位迷宫、散落主路的箱桶货物和需要逐件碰撞的码头设施；缩略图应先读成宽松可探索的岭南港镇，再读出商贸功能。
- 背景不得包含人物、可读文字、UI 或水印；建筑使用灰砖黛瓦、旧木、少量铜金门饰，岛缘用礁石、海水、榕树和红土坡闭合。
- 两名商人使用 3/4 俯视、全身、项目原生 Q 版像素小人独立透明资产，约 2.5～3 头身、大头短身、四肢短小且轮廓清楚；禁止写实成人比例立绘缩小。货栈商人以褐/靛色和账册/算盘为识别点；船行掌柜以深蓝工装、皮护腕和图纸卷/木尺为识别点。
- 商人首版只需静态待机形象，不生成无实际用途的完整动作大图集；人物脚底对齐现有 64×64 LPC 角色尺度，并排时可见高度接近，最近邻过滤。
- 月环商城 UI 使用深墨蓝黑、旧木赭色、低饱和旧纸与克制铜金，商品图像是第一视觉层，价格与主操作是第二层。禁止三个等宽矩形框、卡片墙、为装饰而存在的边框和现代后台仪表盘构图；左侧商人区、中间单列货架、右侧大幅纸质展示台必须形成明显非对称节奏。正文只用深墨或旧纸白，辅助文字只用灰褐，铜金只标识价格、选择和主操作；禁止米黄纸面上的浅黄字。
- 商人区允许布幔、柜台横木、店铺印章和一句招呼形成情境；商品列表使用小图标、行选中底纹与金色箭头；大图区使用较亮纸面托起商品，主按钮位于视线终点。边框只用于组织，不得让整屏看成深色框套深色框。
- 8 种物品图标统一为 3/4 俯视像素道具、透明背景、近似 1:1 画布和一致光源；船型卡使用用户美术组现有舰艇图，不以生图替代。

### 伏波古岭单图像素背景

- 生产方法直接参考第一幕皇宫：一张完整 3:2 横向背景图承载场景空间，角色、交互和 UI 由 Godot 覆盖。参考的是单图构图、像素清晰度和工程简洁度，不照搬皇宫的朱红大殿或北方皇家建筑语言。
- 目标源图约 1536×1024；优先使用生图模型稳定的原生横图比例。不得把多张生成图拼接成大地图，不做局部扩图，也不靠大量透明模块补齐构图。
- 场景必须是明朗、清新、精美的中式像素 RPG 风格：空气感通过浅色地面、短而柔和的阴影和清楚色块表达；像素边缘锐利，细节精致但不堆满碎纹理。
- 主色使用清澈南海青蓝、嫩而不荧光的岭南草绿、红褐与赭红土壤、浅灰砖、蓝灰瓦和旧木赭色；朱红与低饱和铜金只作为军旗、门饰和任务地标的小面积强调。道路和校场是被踩实后略微变浅的红褐夯土，不使用占据全图的浅黄沙地。
- 以现有 64×64 LPC 主角为绝对比例锚点。主要房屋宽约 220–300 像素，普通树冠宽约 80–120 像素，古渠闸口和军鼓约 56–88 像素；道路净宽至少 128 像素，院落与校场保留大片干净可走地面。任何建筑、树木或机关都不能占据半个镜头。
- 岭南辨识度来自植被覆盖的低缓红土丘陵、红壤路切、灰砖黛瓦、镬耳墙或朴素硬山山墙、榕树与荔枝树、竹丛、海风灌木、山泉古渠和近海岸线。守岭院应像地方海防军镇，不像江南园林、皇宫、寺庙或通用奇幻村落。
- 石材是功能材料而不是地貌主体：只在登陆码头、古渠护岸、建筑基脚、短挡土坎和极少量自然露岩中出现。禁止大面积灰色峭壁、石林、环绕道路的连续石墙和遍地散落碎石。
- 地点语言：登陆处只露出局部青蓝海面与低矮石码头；守岭院采用小体量灰砖青瓦、镬耳或朴素硬山建筑，少飞檐、少装饰门楼；古渠是嵌入红土坡的窄石渠与木石闸；校场是开阔红褐夯土地、简易木栅、中式军鼓和素面令旗；观景台以低矮烽燧或土台收束，不建高耸石塔。
- 构图是一处可步行的“岛上局部”，不是一眼看完整岛轮廓的微缩沙盘。陆地和低缓丘坡延伸到画面边缘，海水只在登陆岸与远眺边缘局部出现；五个地点用 S 形道路、院落、林缘和红土缓坡自然串联，不排成规整图标清单。
- 游戏可读性优先于自然写实：主路使用连续、略浅且低噪声的红褐夯土地，活动空地沿用同一材质；禁行坡地与植被使用更深的红土和绿色。道路宽度、色相和明度不能在中途突然消失，也不能与周围裸土混成一片。
- 木围栏不作为地图通用边界，也不沿道路连续出现。使用草缘、低矮土坎、成片树丛和建筑轮廓组织空间；军鼓、渠闸和望海台分别承担阶段地标，每个局部只保留一个主视觉焦点。
- 精细装饰集中在禁行区和地标周围；道路中央、互动范围和角色脚下保持干净。普通镜头中至少约 60% 的可走地面不出现箱筐、散石、木桩、花丛或横向装饰线。
- 地面、道路、建筑、树木、岩石、古渠外观、校场陈设和远景全部烘焙在同一背景图中。只允许把水流高亮、任务标记、剧情障碍、玩家和 NPC 作为独立视觉节点。
- 生成图不得包含人物、文字、UI、Logo、水印、现代物件或无法进入的假门洞；不得出现完整岛屿轮廓、四周海水环绕、巨型建筑、锯齿状石山、灰色峡谷、连续木围栏、杂乱路障、俯瞰沙盘、等距 3D、柔焦、抗锯齿或写实材质。
- 禁止日式神社、东南亚寺庙、热带度假村、欧式城堡和北方宫殿成为主体；棕榈不得作为主植物，优先榕树、荔枝、竹与岭南常绿灌木。
- 避免两种失败风格：一是深暗厚重、风化过度、写实油腻的“像素写实”；二是色块粗糙、物件像贴纸、细节不足的低质卡通。目标是清爽配色、稳定透视、清楚轮廓和适量精细装饰并存。
- 碰撞由 Godot 根据可走安全区手工绘制，不从图片颜色或 Alpha 自动推导。房屋、屋顶、大型树冠和密林全部处在禁行区，背景无需拆分前后景遮挡层。

- 海上大地图扩展允许由多张同规格背景分块组成；相邻分块必须保持相同俯视角、建筑比例、像素密度、海水色阶和光照方向。
- 分块连接边预留至少约 5% 的平静海水衔接带，不在接缝上放置主要岛屿、建筑、地点入口或高对比浪花；场景可用短距离 Alpha 渐变叠放消除色差。
- 扩展图不得烘焙地点名、玩家船只、事件船、路线、UI、边框或水印；所有可进入地点与交互提示仍由 Godot 节点投影。

## 标题界面

- 启动主视觉采用 3:2 横向像素水墨场景，与 1344×896 基准画布一致：岭南海疆晨雾、远山、港湾和水师楼船构成原创叙事画面。
- 构图借鉴成熟单机游戏的强主视觉与克制纵向菜单层级，但不得复制任何现有作品的人物、Logo、地形或装饰。右侧承担楼船与主帅剪影焦点，左侧保留低对比雾海和宣纸留白供标题与菜单使用。
- 色彩延续黛青墨黑、旧纸米色、朱红和低饱和铜金；像素边缘清晰，水墨雾层克制，不使用写实摄影、现代霓虹或高饱和奇幻光效。
- 背景不得包含文字、按钮、Logo、水印或可识别第三方元素。标题和菜单必须作为独立 UI 层，以便适配窗口并提供交互状态。
- 标题使用单独生成并去除色键背景的“厂车英雄传”黑墨暗金书法素材，不再叠加章节题签、副标题或版本说明。
- 四项主菜单统一使用单独生成并去除色键背景的横向水墨按钮底板：深黛青墨芯、干笔墨锋和少量旧金竖向点缀。底板不烘焙文字或图标，中文由 Godot 覆盖；悬停和键盘焦点通过轻微提亮与暖金文字表达。
- 标题界面保持简洁有力，除“继续游戏、开始新游戏、游戏设置、退出游戏”外不常驻显示存档状态或其他说明；只有读取失败时才临时显示必要错误。

## 海战教程提示

- 新手教程提示使用约 `720×164px` 的横向干笔墨条，不使用旧纸矩形卡片、顶部目标卡片或规整描边框；墨条紧接战斗顶部第二行文字下方，中央黛青黑墨面保持平静，两端保留完整干笔飞白。
- 生图素材只包含墨迹底纹，不烘焙中文、步骤数字、按钮、印章、舰船或战场背景；所有文字和交互由 Godot 控件叠加。
- 标题采用金色并写成“第一步 · 选中舰船”一类的步骤结构，字号为 `24px`；正文与收起/展开入口采用 `20px` 米白色，标题比其他文字高一档，所有文字均使用纯黑描边，确保复杂海面上可读。
- 墨条、标题和正文均以战斗视口中线水平居中，不为右侧收起/展开入口让位；入口固定在墨条右上角，与金色标题行垂直居中，距墨条右边界约 `20px`，不得侵入会换行的正文区域。
- 当前目标完成后，旧提示自动淡出，内容切换至下一步后淡入；不显示上一页、下一页和页码按钮。收起/展开入口置于墨条右侧安全区内，使标题、正文与入口共用同一笔触背景。
- 收起教程后隐藏完整墨条与教程文字，但“展开”入口必须保留一条紧凑干笔墨签作为底纹，并在小墨签中水平居中；重新展开时小墨签隐藏，按钮回到完整墨条右上角，禁止让入口文字单独悬浮在战场上。

## 海战劝降交涉

- 劝降交涉复用新手教程的透明像素水墨干笔墨条，不再使用独立宣纸、布帛或规整卡片框；标题、正文和操作文字直接叠加在墨迹安全区。
- 劝降墨条、标题、正文和操作入口全部对齐新手教程规格：`720×164px` 墨条、`24px` 金色标题、`20px` 米白正文与操作文字；标题和正文使用 `4px` 纯黑描边。
- 决策按钮常态只显示带黑描边的文字，不显示矩形底框；悬停与按下时才出现克制的朱砂或墨青反馈。

## 海战动态海面

- 海面底图允许保留原始水墨云浪构图，但运行时平铺必须使用边界连续的镜像循环采样，不得以 `fract()` 直接硬拼原图左右或上下边缘；镜头平移和缩放时都不能看到矩形分块线。
- 水波亮纹只作低对比度动态点缀，当前折射亮纹强度上限为 `0.14`；不得因多层亮度提取放大源图边缘差异，形成固定的横线、竖线或规则网格。

## 海战多格地形印章

- 海滩、森林、草地、港口、小镇和陆河不再以“每格一枚独立图标”作为正式目标；允许一张透明地貌素材跨越多个逻辑格，形成连续海岸、林带、港镇或河谷。
- 多格素材必须带有确定的逻辑占地和地形掩码。图片只负责表现，移动、碰撞、视野和射程始终读取底层格子数据；禁止从图片颜色或 Alpha 自动推导规则。
- 河流不得作为孤立装饰随机落在海面或地图中央。河流印章必须自带或连接明确的内陆源头、连续河道和海岸河口；若随机地图找不到满足边界、布阵区、出口与连通性条件的位置，本局可以不生成河流。
- 首版校准印章为 `6×8` 河口岛：上部林地形成源头，中部草地承接连续双格河道，下部海滩形成入海口；素材外围和河口外侧保持真实透明，使运行时海面自然透出。
- 多格地貌使用项目现有俯视偏正面的手绘像素水墨语言，轮廓必须在战斗默认倍率下清楚；不得包含格线、文字、船只、UI、交互标记、水印或覆盖整块矩形的海水底色。
- 多格印章以战场海面底图的低饱和灰青、烟玉、灰橄榄、旧赭和宣纸米色为母色；树冠合并为大块墨团并使用清楚的阶梯像素轮廓，不绘制写实叶片、亮翠植被、热带明信片棕榈或大量高频微细节。河水须落在海面的蓝灰色系，河口以稀疏横向墨纹和透明渐隐接入运行时海面，不得自带大块亮青水体或浓白浪花。
- 运行时允许在地貌之上继续绘制迷雾、移动范围、射界和目标高亮；素材内部不依赖重复单格图补足细节，零碎未覆盖区域才使用单格素材兜底。

## 海战战争迷雾

- 视野外区域使用透明背景的白色像素水墨海雾组件，颜色限定为米白、淡蓝灰和低饱和玉青灰；禁止继续使用黑色或深灰色逐格矩形遮罩。
- 大范围透明干笔雾纹跨格交叠并以轻微位置、尺寸扰动形成连续不规则边缘；不得使用高倍率下可辨认的规则圆雾，不得每格重复同一贴图，也不得把棋盘格、海面、船舰、岛礁、文字或矩形底色烘焙进组件。

## 海域探索迷雾

- 海上大地图和完整海图的未知海域直接复用海战 `white_ink_mist_v1.png` 白色像素水墨海雾组件；两处共用一套粗表现格，按海战同款哈希、尺寸和位置偏移布置大范围透明干笔雾纹，禁止把单片素材按行高频平铺，也禁止继续输出纯黑或深灰探索遮罩。
- 探索位图只裁切最终雾层，不给素材染成黑色。雾色保持米白、淡蓝灰和低饱和玉青灰，半透明覆盖下仍能辨认海面与岛屿的大体结构。
- 大地图与完整海图必须共享同一张世界坐标固定的分格雾笔密度纹理；每片雾保留素材自身飞白，局部叠加数量变化形成浓淡层次和小孔洞。禁止用统一高底雾抹平纹理，也禁止对多层颜色做全屏平均；两处都保持稳定、不随时间闪烁。
- 未探索区域的雾笔下方必须先铺同源水墨海水纹理，完整遮蔽背景地图中的岛屿、港口与陆地。雾中飞白和孔洞只显示海水层；禁止让未知地形以低对比度剪影透过雾层，真实地形只能在探亮后出现。
- 白雾只改变未知区域表现，不改变永久揭示范围、地点名称显隐、玩家标记层级或存档数据。

## 章节过场

## 场景二对话 UI

- 第一章和第二章统一使用生成式横向像素水墨笔触作为对话底板：墨色主体略微透明，四周为透明墨锋，正文直接叠加在中部平静区域，不再使用米黄色纸张或矩形卡片作为视觉主体。

- 第一章正文采用较窄行宽并位于底板右上方安全区；第二章有选项时，正文与选项作为整体垂直排布，最下方选项仍需留在墨迹内部。

- 剧情选项的悬浮、按下和键盘焦点状态仅把文字变为暖黄色，所有状态的底框保持完全透明，不显示矩形高亮。
- 场景二、海图事件和伏波古岭角色对白统一复用 `FieldEventDialogue`；NPC 使用右侧 440×520 透明立绘与右下笔刷姓名牌，伏波守岭人暂用士兵立绘，不再新增近似对话框。
- 可交互人物靠近时只增加贴合像素轮廓的暖金亮边，并同步显示底部 300×74 水墨按钮；人物本身不得缩放或改变颜色，离开后移除亮边，不使用脚底圆环或矩形世界高亮。
- 对话人物紧邻底板两侧：水师主帅固定在左，所有 NPC 固定在右；说话者姓名铺在人物下方的独立短水墨笔触上。无人物旁白只显示正文底板。

- 对话 UI 不显示自动播放、长按跳过和其他参考图中的附加操作，只保留项目现有的点击/空格继续与剧情选项。
