# 3v3 海战棋盘海水表现设计

- Status: approved for implementation
- Date: 2026-08-05
- Scene: `res://scenes/naval_tactics_v3.tscn`

## Goal

把素材库中与现有 Kenney 船只同源的海水正式用于 3v3 棋盘，消除纯色方格海面的临时感，同时维持战棋所需的格线、攻击范围、航标、岛礁和敌我识别清晰度。

## Selected approach

使用 Kenney Pirate Pack 的 `PNG/Default size/Tiles/tile_73.png`。它是 64×64 的无缝海水格，与当前 62×62 棋盘格尺寸接近，且和玩家、敌方船只属于同一套非像素美术。素材复制到项目稳定路径 `res://assets/sprites/naval_tactics/water_tile.png`，来源和 CC0 许可写入 `assets/THIRD_PARTY.md`。

海水纹理只替换棋盘格的纯色底面。棋盘外框、格线、机动/攻击范围、合法目标、岛礁、航标、船只状态和 HUD 的现有绘制顺序保持不变。海水使用深海蓝调制，避免原素材的亮青色降低文字、舰船和范围色块的对比度。

## Rejected alternatives

1. Tiny Islands 16×16 像素海水：虽然也是 CC0，但与当前平滑 Kenney 船只和岛礁风格冲突。
2. 继续使用纯程序双色海面：可读性稳定，但没有使用现有素材，临时原型感最强。
3. 新增动态海水着色器：会扩大本次改动、增加闪烁和范围识别风险；等静态素材通过实机可读性检查后再单独评估。

## Runtime structure

`TargetTacticsController` 预加载海水纹理，并在 `_draw()` 中先绘制现有深色后备底面，再把纹理逐格铺到 12×8 棋盘。纹理绘制在所有玩法覆盖层之前，因此不会盖住机动范围、攻击范围、合法目标或格线。规则模型、寻路、鼠标命中和船只节点不读取海水纹理，也不新增海域规则。

如果纹理无法加载，控制器仍保留现有 `SEA_A`/`SEA_B` 双色后备底面，场景不会因为纯表现资源缺失而失去可玩性。纹理使用线性过滤，与现有 Kenney 船只一致；不修改全局导入或缩放设置。

## Acceptance checks

- 3v3 场景能够加载项目内的 `water_tile.png`，并在全部 96 个棋盘格内绘制海水。
- 海水绘制发生在攻击/移动覆盖层、格线、岛礁、航标、船只和 HUD 之前。
- 原有点击坐标、移动范围、攻击范围和规则验证结果不改变。
- 1280×720 实机截图中，海水纹理可见，格线、蓝红船只、航标和范围提示仍然清楚。
- `assets/THIRD_PARTY.md` 记录原文件名、作者、来源、CC0 许可和项目内路径。
- V3 规则、真实动画流程、旧版海战和官船成长回归保持零失败。
- 完成后重新启动 `naval_tactics_v3.tscn`。

## Scope limits

- 本次不制作动态潮汐、天气、浅水、洋流或海域加成。
- 本次不替换船只、岛屿、航标、特效或 HUD。
- 本次不把 V3 视觉改动接入 V2.6 官船生涯场景。
- 静态水面是否需要动态化，必须根据后续实机截图与真人试玩另立变更。

## Verification strategy

先在场景契约验证中加入“海水资源存在并由 V3 控制器使用”的失败检查，再复制素材和接入绘制。随后运行 V3 聚焦验证与真实交互验证，捕获 1280×720 OpenGL 画面并检查水面层级和范围对比度，最后回归旧版海战、官船成长和纯规则模拟。
