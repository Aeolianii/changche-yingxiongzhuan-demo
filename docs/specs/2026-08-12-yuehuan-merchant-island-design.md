# 月环商岛可探索商城设计规格

- Status: approved for implementation
- Date: 2026-08-12
- Related change: `docs/changes/CHG-20260812-yuehuan-merchant-island.md`

## 1. 玩家体验

月环商港不再是进入即弹出的总商城。玩家从海图港口进入后，先出现在月环商岛南侧码头；镜头跟随角色，玩家沿主路进入中央商街。岛上至少有两家可辨认的商铺，每家门前站一名负责该铺业务的商人。靠近商人时显示“按 E / 空格交谈”，交谈后显示简短身份说明，并提供“看看货物/图纸”“告辞”选项。只有选择交易选项才打开商城界面。

关闭商城后，玩家仍站在原商人门前继续探索。返回海图不再是商城界面右上角按钮，而是码头登船点的世界交互；它继续使用现有一次性返航上下文恢复登岛前船位。

## 2. 岛屿空间与美术

采用一张约 1536×1024 的完整横向生成背景图，与伏波古岭相同：背景包含地形、建筑、道路、码头和静态装饰；人物、交互提示、对话、商城 UI 与碰撞由 Godot 叠加。视角为清晰的明朗岭南像素 RPG 3/4 俯视视角，保持项目现有 64×64 LPC 人物的比例基准。

构图采用伏波古岭式的宽松探索空间，但核心业态必须具有“月环商港总埠”的规模。海面只出现在画面下方约 20%～25% 区域，形成一段单侧海岸与中央码头；陆地延伸至上、左、右三侧画面外。码头通过至少 260～320 像素净宽的石板轴线进入开阔交易前庭，中央保持连续、大块、干净、无遮挡，能容纳四个 64 像素角色并行。

左侧不是单栋小店，而是由主仓房、侧仓、装卸棚、院墙和成组木料/铁料构成的围合式货栈院，朝向交易前庭设置正式柜台或大门；右侧不是普通民居，而是由宽体工坊、船架、半成品木船、图纸业务门廊和材料棚构成的船行作场。两处业务建筑群轮廓明确、体量接近中型公共设施，门前各留至少 220×160 像素完整空场。货物集中在装卸区和墙脚，船体集中在船架范围，不能散落到主路。上方和两侧以连续院墙、榕树、竹丛和低缓红土坡收边，使商港看起来是长期经营、有秩序的大型商号分部，而不是荒岛上的两间路边铺。

碰撞以用户确认的红线为准，仍采用粗略手工大形状，不逐件描摹摊位、货箱、屋檐或树木。1536×1024 世界中的最终可走轮廓为中央商街 `x=555..960, y=125..545`，向两侧展开的交易前庭 `x=175..1215, y=545..700`，码头入口阶梯 `x=570..930, y=700..730`，以及正式码头 `x=590..905, y=730..1024`。红线外的院内、建筑、植被、悬崖与海面均由阶梯式大矩形阻挡；商人门前空场、中央主路和码头不得放置碰撞。

店铺身份首先由建筑群、院落和生产/仓储陈设表达，不能依赖漂浮在画面上的超大后贴招牌。允许在门楼设置比例合理的素面木匾或行业纹样，但背景不得生成可读文字；准确的“货栈”“船行”名称继续由交互提示和商城 UI 提供。独立招牌资产从正式场景移除。

## 3. 商人角色与职责

### 3.1 货栈商人

- 名称：梁货郎。
- 外观：岭南港口中年货栈掌柜，褐色短褂、靛蓝腰带、袖口利落，携账册或算盘；采用约 2.5～3 头身的大头短身 Q 版像素小人，体型与 64×64 主角协调。
- 站位：货栈门前，旁边可见木料/铁料货堆。
- 对话：说明可购入木材、铁石，也收购玩家从岭南海域带回的鱼货、海货和杂物。
- 交易职责：`goods`。商店侧只出售 `wood`、`ironstone`；玩家仓库侧显示所有库存大于零且 `sell_price > 0` 的物品。木材和铁石可买可卖，其他商品只能卖。

### 3.2 船行掌柜

- 名称：沈船师。
- 外观：岭南老练造船师，深蓝工装、皮护腕、卷起袖子，携图纸卷或木尺；采用约 2.5～3 头身的大头短身 Q 版像素小人，与货栈商人轮廓和颜色明显不同。
- 站位：船行门前或船架旁。
- 对话：说明先购图纸，图纸永久有效；之后使用军饷、木材和铁石重复建造对应船型。
- 交易职责：`shipyard`。只显示三类图纸和已解锁船型的造船操作；不显示普通货物收购。

商人本身是静态 NPC，不移动、不参与碰撞推动；其脚下设置小型阻挡，周围设置交互范围。交互范围只决定提示和对话，不直接执行交易。

## 4. 交互与状态流

场景状态依次为 `EXPLORING`、`DIALOGUE`、`SHOP`、`TRANSITIONING`。一次只允许一个状态：

1. `EXPLORING`：角色可移动；进入商人交互范围显示提示。
2. 按交互键进入 `DIALOGUE`：角色停止，显示 `FieldEventDialogue`；选择交易或告辞。
3. 选择交易进入 `SHOP`：隐藏对话，打开对应职责的商城覆盖层，角色保持停止。
4. 关闭商城回到 `EXPLORING`：刷新附近交互提示和经济 HUD。
5. 在码头交互进入 `TRANSITIONING` 并返回海图。

当多个触发范围异常重叠时，按玩家与商人/码头锚点距离选择最近目标。界面、对话或转场开启时忽略额外交互输入，避免重复开店或多次返航。

## 5. 商城 UI

商城使用用户参考图的“双栏交易”原则，但每名商人的界面只展示自己负责的业务。覆盖层保留半透明暗幕，使玩家仍能感知自己处于岛上商铺门前。

- 左栏：当前商铺商品/业务列表。货栈显示木材、铁石；船行提供“造船图纸”和“造船行”两个页签。
- 右栏：玩家大仓库。货栈显示可出售物品与数量；船行显示已购图纸、舰队数量和所选船型成本。
- 下栏：名称、来源/用途、单价或建造成本、数量步进器、购买/出售/建造按钮、结果提示、当前军饷。
- 右上：关闭按钮，只关闭商城回到岛上；返航必须去码头。

商城覆盖层调用现有 `GameState` 公开交易方法，不直接写库存。失败时显示原因且不改变资源。货栈出售数量可批量，造船每次建造一艘。

### 5.1 商城视觉与信息层级（2026-08-12 修订）

进入 `SHOP` 状态时，共享 `ExplorationUI` 整体隐藏，包含角色头像、任务栏、任务/人物/物品栏/船只/菜单按钮和提示；商城关闭并回到 `EXPLORING` 后恢复。商城自身使用接近不透明的深墨蓝/旧木/宣纸面板覆盖全屏，只保留少量场景氛围，不允许背景 HUD 穿透造成遮挡。

商城采用成熟单机 RPG/战棋商店的非对称任务层级，而不是三块等宽后台面板：

- 左侧约 22% 为商人氛围区：显示商人全身像、姓名、店铺名、简短招呼和当前业务图章，背景以木构柜台、布幔和暗纹建立“正在与掌柜交易”的关系，不承载密集数据。
- 中间约 31% 为唯一商品列表：一列大行项目，每行包含 72～84 像素图标、名称、价格/库存状态和明确选中游标；最多同时显示 5～6 行，可滚动。不得做两列小方格商城或均分卡片墙。
- 右侧约 47% 为视觉焦点：宣纸/旧木展示台上呈现 220～300 像素商品或舰船大图，下面依次是品名、用途、来源/成本、数量与唯一主操作按钮。视觉焦点不得再被第三个库存面板分走。
- 容器不是装饰：不得给商人、问候、店名、资源条、商品标题和每段说明分别套方框。画面仅保留一块主商品展示纸面，以及数量输入、主操作按钮等具有真实交互意义的控件；其余层级靠留白、对齐、细分隔线与单侧选中标记完成。
- 每屏只保留会改变玩家交易决定的文字：商品名、单价/成本、持有量、数量/合计、主操作；商人姓名与店名只在顶部出现一次。删除重复的“在售货品/货品详览”、重复店名、商人口号和来源长文。
- 文字颜色固定为三层：纸面正文使用深墨 `#2c2821`，辅助信息使用灰褐 `#756b59`，铜金 `#bd8b38` 只用于价格、当前页签/商品和主操作。深色背景正文使用旧纸白 `#d8cfb8`；禁止亮黄色正文、浅黄色标题叠在米黄纸面、以及多种金色同时出现。

### 5.2 商人环境吆喝

- 两名商人在玩家自由探索时使用头顶小型像素对话气泡随机吆喝，每次只显示一句不超过 14 个汉字的业务短句，显示约 2.5 秒，间隔随机 5～9 秒。
- 气泡不接收输入、不改变玩家状态、不替代交互提示，也不自动开启对话。只有玩家进入商人交互范围并按 `E/空格` 才进入原有满屏对话。
- 对话、商城或全局菜单出现时，全部环境气泡立即隐藏并暂停；回到探索状态后重新以随机间隔开始。

### 5.3 商城交易效率与空间（2026-08-12 修订）

- 商城主内容采用约 4:6 分区：左侧完整用于模式标签、当前持有提示与可滚动商品列表；右侧用于商品大图、名称、核心价格/成本、交易预览和操作。商人 Q 版头像缩至标题栏店名左侧，不再占一列。
- 商品行固定为“像素图标—名称—右对齐价格”，hover 使用轻微亮底，选中项使用更明显的浅底与铜金左线。模式标签的选中态同时使用浅背景与铜金下划线。
- 商品交易数量允许键盘直接输入，范围从 0 到 9999；提供 `+10`、`+100`、`最大` 与 `清空`。购入最大值取 `军饷 / 单价`，出售最大值取该商品当前持有量；“全部出售”直接出售当前商品的全部持有量。
- 数量变化即时显示“交易后军饷”和“交易后持有”。数量为 0、购买金额超过军饷、出售数量超过持有量、图纸已拥有或造船资源不足时，主操作按钮进入明确禁用态。
- 底部状态栏拆为军饷、木材、铁石、舰队容量四个等距资源块，并复用对应像素图标。项目物品仓库无容量上限，因此不得出现虚构的“货仓容量”；舰队仍准确显示 `当前舰船/10`。
- 货栈顶部模式为“购入木铁 / 出售货物”。购入模式的列表只有木材和铁石；出售模式用同一中间列表显示玩家所有可出售库存，因此玩家货舱不常驻占屏。
- 船行顶部模式为“购买图纸 / 船坞建造”。图纸列表显示三种船与永久解锁状态；建造列表只显示已解锁船型。
- 底部细资源条只显示军饷、木材、铁石和舰队容量，作为辅助反馈，不建立第四个大面板。

木材、铁石、黄花鱼、大石斑、青蟹、旧靴子、龙井茶、私盐使用同一套 3/4 俯视像素图标，透明背景、轮廓清楚，可在 64～96 像素尺寸阅读。三种船型禁止重新生成，分别使用用户美术组的三张舰艇资源，经无损裁切和去白底后成为商品展示图。

## 6. 数据与兼容

不增加新的商品、价格或持久状态。现有 `EconomyState`、图纸列表、船只数组和军饷继续作为唯一数据源；现有版本 2 存档结构不变。岛上商人身份和位置属于场景静态内容，不写入存档。月环商港场景路径保持不变，因此海图入口与旧存档待进入场景不需要迁移。

## 7. 验证策略

- 静态/自动化：场景包含背景、玩家、粗碰撞、两个商人和码头触发；商人职责映射正确；货栈不能购买特产；船行不显示货物；商城打开/关闭切换移动锁；返航仍写入原有请求。
- 经济回归：原有买卖、图纸、造船、舰队上限、存档 V1→V2 测试继续通过。
- 引擎检查：Godot 4.7 加载场景无解析错误；运行指定商岛场景，分别走到两名商人和码头实测。
- 视觉检查：1344×896 截图确认码头轴线、交易前庭、围合货栈院、宽体船行作场、人物比例、提示、对话与两个商城覆盖层可读；商城截图中共享 HUD 必须完全隐藏，商品/船只图像、价格、库存、选中状态和主操作具有明确视觉层级；开启可见碰撞确认主路线宽阔且碰撞保持少量大形状。

## 8. 首版明确限制

首版只有两名商人和两个业务集合；不进入室内、不制作 NPC 行走动画/日程、不加入动态库存与物价、不制作逐像素碰撞。后续新增商铺时，应新增明确的商人职责和真实商品产出文档，而不是把所有功能重新塞回一个总商城。
